# Blog post writing

- Treat the blog as a long-lived personal notepad about Linux and computing.
  Write primarily for the author's future self, who may need to find and
  understand the note years later; other readers are welcome too.
- Start with the concrete problem or goal and give enough context to recognize
  when the note applies. Use searchable titles and relevant tags, including
  software, distro, or version names when they matter.
- Keep posts brief when the subject allows it, and prefer simple how-tos over
  long essays. Do not remove the context, rationale, prerequisites, exact
  commands, or caveats needed to make the note useful later.
- Use a conversational, direct tone. First person is fine for the author's
  actual experience; do not invent personal anecdotes or generalize from one
  setup without saying so.
- For how-tos, state requirements and show reproducible steps with concise
  commands or examples. Use short headings when they help scanning.
- Avoid padding, repeated summaries, generic introductions, and marketing
  language. Link to a published script or other long source instead of
  reproducing all of it when a link is available.
- Follow the existing Hugo front matter conventions in `content/posts`.
- Posts written or edited with LLM assistance must end with an italicized
  attribution in this format: `*Assisted by LLM model: Name Version*`. Replace
  `Name Version` with the actual model name and version used.
